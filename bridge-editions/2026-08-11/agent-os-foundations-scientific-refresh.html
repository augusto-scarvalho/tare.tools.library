5. Scientific and engineering evidence — 2026 refresh

The OS analogy is strongest at the user-space substrate boundary, not at device/kernel replacement. Agent libOS [R01] and OS-security analyses [R02] independently converge on identity, lifecycle, capabilities, isolation, scheduling/checkpointing and audit as runtime concerns.

Recent harness research treats the harness itself as a durable engineering asset. AHE [R03] localizes improvements to tools, middleware and memory and evaluates frozen transfer; Code as Agent Harness [R04] similarly moves attention from prompt cleverness toward executable, verifiable system structure.

Determinism should be placed in authority, invariants and effects rather than forcing deterministic reasoning. CAAF [R05] is useful as evidence for executable invariants, but tare should avoid importing a monolithic alternative architecture.

Skills, prompts and playbooks remain behavioral knowledge, not authority. Skill-mediated architecture work [R06] supports run-specific binding; in tare that binding should occur beneath policy/eligibility and above runtime execution, never create a second authorization model.

Durability is now standard practice rather than speculative. Microsoft [R07] and Google/Temporal [R08] show production patterns in which agent logic and durable execution can be composed. That strengthens backend-qualification rather than framework lock-in.
