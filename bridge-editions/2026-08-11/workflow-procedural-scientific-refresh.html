5. Scientific and engineering evidence — 2026 refresh

TraceCompiler [R01] is unusually aligned with tare: recurring noisy trajectories can be compiled into mostly deterministic procedures, but only dependency relations backed by evidence become hard edges; underdetermined irreversible effects trigger refusal rather than invention.

Microsoft AWO [R02] shows a less radical version of the same idea: recurrent tool sequences can become deterministic meta-tools, reducing reasoning steps and some failures. This suggests procedural materialization should be an optimization layer over evidence, not the default authoring model.

Runtime-structured decomposition [R03] reinforces moving control flow out of monolithic prompts. For tare, the stronger implication is heterogeneous nodes with explicit ownership and effect semantics, not simply a nicer agent graph.

Durable-agent offerings [R04][R05] make crash recovery and waiting implementation-real, but backend replay constraints must not dictate tare's authority/effect ontology.

AHE [R06] suggests workflow optimization should log predictions and measure transfer, while the broader agent survey [R07] confirms that latency, reliability, context growth and tool variability must be part of evaluation rather than only final success.

Statistical treatment should match the design: paired confidence intervals or bootstrap for repeated task suites, survival/time-to-event when latency/recovery matters, and calibration/regret metrics for prediction/routing problems.
