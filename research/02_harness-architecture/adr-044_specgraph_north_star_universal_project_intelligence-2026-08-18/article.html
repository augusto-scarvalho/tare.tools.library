ADR-044: North Star do tare.tools-specgraph — Plataforma Universal de Project Intelligence & Spec-Driven Development (SDD)

Estudo formal de arquitetura para o tare.tools Agent OS.

RESEARCH / PEER-REVIEW RATIFIED DRAFT. Publicação em tare.tools.research sob governança de Design Science. Não concede isoladamente autorização de mutação em repositórios de produção sem o protocolo canônico do Relay Mesh.

1. Escopo & Formulação do Problema

O desenvolvimento acelerado de software por equipes humanas e swarms de agentes autônomos enfrenta um gargalo crítico de amnésia contextual e perda de intenção:

  1. O código evolui rapidamente, mas os motivos das decisões (ADRs/Specs) se perdem, causando documentation drift.
  2. Ferramentas de busca vetorial (RAG) encontram similaridade estatística, mas são cegas para causalidade e dependências lógicas.
  3. Indexadores estáticos (Graphify/SCIP) mapeiam a sintaxe do código, mas não entendem a intenção de negócio nem verificam critérios de aceite.

O tare.tools-specgraph foi concebido para resolver essa lacuna, transformando o desenvolvimento de software através do paradigma SDD (Spec-Driven Development) e da Matriz Viva de Rastreabilidade Causal:

$$\text{Requisito / Intenção} \longrightarrow \text{Design / Spec / ADR} \longrightarrow \text{Tarefa (DAG)} \longrightarrow \text{Código (AST)} \longrightarrow \text{Teste (Falsifier)} \longrightarrow \text{Evidência (Attestation)}$$

2. Método & Trilha de Evidências

A. Desacoplamento Total do Microkernel (tare-kernel):

  • O tare-kernel é o runtime de baixo nível para sandboxing, CAS atômico e atestação de agentes.
  • O tare.tools-specgraph é uma plataforma e biblioteca independente, modular e universal:
    • Funciona diretamente para desenvolvedores humanos via CLI (specgraph) e visualizador Web interativo;
    • Funciona para qualquer agente de IA do mercado (Claude Code, OpenAI Codex, Cursor, Aider, Copilot);
    • Opera 100% local-first com latências sub-50ms na máquina do usuário.

B. Sintaxe Concreta e Baixo Custo de Anotação:

  • Specs: Frontmatter YAML com implements: [REQ-01] e target_symbols: [...].
  • Código: Docstring tags (@spec SPEC-042) ou mapeamento declarativo specgraph.yaml (zero-touch no código).
  • Testes: Marker pytest nativo @pytest.mark.verifies("SPEC-042", "AC-01").
  • Dependências: DEPENDS_ON_STATIC inferidas 100% por AST a partir dos imports do código.

C. Escopo Delimitado de Governança (governed_paths):

  • O gate de Zero Código Órfão aplica-se estritamente sobre arquivos declarados em governed_paths (ex.: src/), excluindo fixtures, scripts temporários e código gerado em excluded_paths.

D. Identidade Content-Addressed e Idempotência Estrita:

  • Gerações do grafo são puramente content-addressed: $$\text{generation_id} = \text{sha256}(\text{tree_hash} + \text{canonical_specgraph_digest})$$ Reindexar o mesmo código produz exatamente o mesmo hash sem poluir o ledger.

E. Trust Tiers de Evidência:

  • Tier 1 (Autoritativo): Testes re-executados e atestados pelo CI com hash verificado. Apenas este Tier aprova gates de merge.
  • Tier 2 (Inferência Estática): Imports e re-bindings assistidos confirmados.
  • Tier 3 (Consultivo): Sugestões semânticas de linguagem natural para o comando explain.

4. Consequências e Benefícios

  • Preservação de Intenção: Nenhuma decisão ou critério de aceite se perde durante a evolução do código.
  • Redução Drástica de Tokens: Agentes recebem apenas o fecho transitivo exato necessário para a tarefa ($\ge 65%$ de economia de contexto).
  • Sem Falsos Bloqueios: Fixtures e scripts utilitários não exigem specs artificiais.
  • Soberania e Velocidade: Operação 100% offline, local e determinística.
