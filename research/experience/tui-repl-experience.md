## Thesis

**Chat-first, progressive operational disclosure, control-on-demand.** The interface should expose compact persistent state for frequent/important facts, transient activity for temporary work, inspectors for depth, durable dialogs for authority-sensitive decisions and a Stable REPL for automation/accessibility/power users.

## Ownership

TUI/GUI does not own model binding, approvals, session truth, evidence or resources. It projects objects owned by Routing/Runtime, Authority, Workflow, Capability, Memory and Evidence.

## Steering

Plan-centric/local steering is preferable to restarting long work. Material edits should become typed work/revision/GraphPatch intents and re-enter Authority/Routing paths.

## Explainability

Use causal summaries centered on decisions, effects, evidence and divergence. Raw traces remain available but are not the primary explanation.

## UX evaluation

Screenshot similarity is not correctness. Evaluate state/journey coverage, authority failures, recovery, command semantics, trace comprehension, interruption burden, accessibility and actual task outcomes.

## Surfaces implied by Agent OS

Project admission, Authority/Permits, Workflow/topology, Evidence/Assurance, Runtime fleet, resources/economics, incident/recovery, memory provenance, evolution review and qualification — but disclosed progressively rather than as an always-on dense dashboard.
