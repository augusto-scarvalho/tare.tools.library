Experience, Human Interface & Legacy Reconstruction

Uma interface que projeta o Agent OS sem possuir sua verdade — e uma metodologia para transformar sistemas cognitivos legados em semantics/procedures, não em prompt dumps.

1. Tese consolidada

Experience é projection + steering. TUI/GUI/REPL não devem possuir session truth, model binding, approvals ou evidence; devem tornar legíveis os objetos canônicos e emitir intents/revisions pelos mesmos paths governados usados pelo restante do sistema.

2. Chat-first, progressive operational disclosure

O corpus converge para uma superfície principal simples, com estado persistente somente quando frequente/importante; atividade transitória em strips; detalhes em inspectors; decisões de autoridade em dialogs duráveis. Dense dashboards e raw trace walls aumentam carga cognitiva sem necessariamente aumentar compreensão.

Plan, Workflow revision, Route/Runtime binding, Permits, effects, evidence e resources devem aparecer como projeções causalmente conectadas. “Por que fez isso?” deve ser respondível por lineage, não por explicação pós-hoc inventada.

3. Stable REPL como contrato de experiência

Uma interface textual/machine-consumable estável evita que automations, accessibility tooling e power users dependam de scraping visual. GUI/TUI pode evoluir sobre o mesmo semantic command surface. A experiência humana e a programática devem ver os mesmos objetos, respeitando scope/authority.

4. Steering localizado, não restart

Plan-centric interfaces permitem editar uma subestrutura e preservar progresso. Steering deve produzir typed work intent/GraphPatch/revision request, não alterar state invisivelmente. Mudança material retorna a Authority e, quando necessário, Routing.

Causal trace summaries devem privilegiar decisões, effects, evidence e divergências; telemetry volumosa fica disponível sob demanda.

5. Legacy cognitive reconstruction

A pesquisa de NLU/state-machine reconstruction adiciona um segundo uso importante do Experience/Workflow boundary: sistemas Dialogflow/Watson-like carregam semantic/procedural/transactional knowledge. A migração correta não é “trocar intents por LLM”.

intents/entities/variables/pages/handlers/APIs/logs
 → semantic reconstruction
 → ontology + control graph + data/capability/knowledge model
 → Project Model
 → procedure/subworkflow candidates
 → governed Workflow/Capability execution

Regras/automata permanecem determinísticos onde são conhecidos; LLM pode interpretar linguagem/ambiguity, mas não precisa substituir procedure já explícita.

6. UX correctness

Screenshot similarity é insuficiente. Avaliação deve cobrir states/journeys, authority failures, recovery, semantic commands, trace comprehension, human interruption e task outcomes. UI generation a partir de referências deve preservar provenance/originality e trajectory safety.

7. ADOPT / ADAPT / RETIRE / OPEN

ADOPT

chat-first; control-on-demand; plan-centric steering; Stable REPL; causal summaries; journey/state evaluation; semantic reconstruction.

ADAPT

model picker → Route projection; approval ticket → Authority projection; agent tree → Workflow/runtime projection; NLU graph → procedure candidates.

RETIRE

TUI-owned truth; always-on dashboard; raw logs as explainability; screenshot correctness; “LLMify everything” migration.

OPEN

interaction grammar; causal-summary metrics; human attention budgets; authority UX failure taxonomy; semantic visual regression.

Absorve UX agent studies, GUI/CLI feature surveys, IDE research, TUI/REPL archaeology e NLU/state-machine reconstruction research.

Experience torna o sistema legível e steerable; não ganha direito de redefinir o que o sistema é.
