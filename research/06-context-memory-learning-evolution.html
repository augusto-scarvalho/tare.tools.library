Context, Memory, Learning & Evolution

Contexto como projection temporária, memória/procedures como conhecimento qualificado e evolução como promoção externa ao loop que aprende.

1. Tese consolidada

Project truth não deve depender da janela de contexto. Context é uma view compilada do estado durável; memory e playbooks informam; feedback é sensor; experiência qualificada alimenta candidates; somente evidence independente promove mudança persistente.

2. Context lifecycle

O corpus antigo tratava compaction/summaries como mecanismo central. O refinamento posterior distingue:

  • canonical/durable references;
  • recoverable execution episodes;
  • working scratch;
  • behavioral guidance/playbooks;
  • ephemeral model history.

Context compilation deve ser dependency-aware, policy-filtered e budgeted. A preferência é substituir conteúdo já materializado por refs reidratáveis, não por summary sem provenance. Semantic summary permanece derivative de último recurso, nunca prova.

Rehydration deve verificar source identity/freshness e preservar required dependencies. Estudos AdaCoM/structured eviction sugerem que políticas ótimas podem variar por agent/runtime; portanto compaction é candidato a qualification, não regra global única.

3. Skills, playbooks e procedures

Guidance não concede authority. Um playbook/procedure precisa de provenance, version, applicability/scope e precedence. Trajectories bem-sucedidas podem revelar estrutura; estrutura repetidamente validada pode virar machinery determinística.

Agents discover structure; proven structure becomes machinery. Esta frase conecta memory, workflow compilation e evolution sem transformar cada insight em prompt permanente.

4. A unidade de aprendizado é experiência qualificada

Experience / feedback
 → Finding or hypothesis
 → Attribution
 → Learning eligibility
 → Memory / Procedure / Strategy candidate
 → replay / holdout / shadow
 → independent evidence
 → governed promotion

EffectReceipt não é reward. Operational success, desired outcome e causal contribution são claims diferentes. Attribution precisa lidar com multiple contributors, delayed outcomes e counterfactual uncertainty.

5. Scope of evidence bounds scope of learning

Uma experiência execution-local não autoriza regra platform-wide. O caminho seguro é local → project → project-class → platform somente com replicação/transportability. Global priors podem ajudar; project-local posterior deve prevalecer quando evidence é suficiente.

Learning Invalidation é tão importante quanto promotion: se um upstream artifact/policy/runtime muda, beliefs derivadas podem ficar stale sem que seu historical evidence “desapareça”. Strength e freshness devem ser distintos.

6. Self-evolution sob controle

O learning loop não pode possuir a autoridade que promove sua própria mudança. Candidates são avaliados em replay/holdout/shadow, depois canary/rollback conforme risco. Evolução de evaluators exige metrology porque mudar o judge muda a medição.

Same-model cyclic roles podem aumentar qualidade por externalized artifacts/falsification/test-time compute, mas continuam epistemicamente correlacionados; não contam como independent EvidenceFamily.

7. ADOPT / ADAPT / RETIRE / OPEN

ADOPT

context projection; dependency-aware eviction; rehydration; guidance provenance/scope; scoped learning; independent promotion; invalidation/freshness.

ADAPT

hierarchical memory → projections over durable work/evidence; compaction summaries → last-resort derivative; inheritance → applicability + precedence.

RETIRE

transcript as project state; permanent prompt prefixes; self-written summary as proof; feedback as truth; reputation/memory as authority.

OPEN

context validity model; poisoning resistance; project archetypes; transportability; learning invalidation graph; federated/private experience.

8. Programa experimental

  1. Context policy bake-off por runtime/agent: full transcript, references, structured eviction, summaries.
  2. Golden dependency tests: eviction nunca remove única cópia necessária à execução/reconstruction.
  3. Procedure mining em shadow: comparar agentic step sequence com deterministic replacement.
  4. Project-local vs cross-project transfer com negative-transfer metric.
  5. Delayed outcome/revocation: medir tempo até invalidar beliefs stale.
  6. Same-model CMRP versus compute-matched iterative baseline e independent reviewers.
