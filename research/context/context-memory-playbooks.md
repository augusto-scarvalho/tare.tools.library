# Context, Memory & Playbooks — preservation edition

**Status:** RESEARCH. Keeps the substantive context/memory/playbook lineage distinct from general learning.

## Project truth is not the context window

Context is a temporary compiled projection. Durable canonical state, recoverable execution episodes, working scratch, behavioral guidance and ephemeral model history have different lifecycles.

## Context compilation

Prefer dependency-aware, policy-filtered, budgeted assembly. Replace already materialized material with rehydratable durable refs when possible. Opaque semantic summaries are last-resort derivatives and are not evidence.

## Compaction/eviction

More context is not monotonically better. Stale/wrong context can create contextual drag; compaction can silently erase governance constraints. Structured/typed eviction and agent-compatible policies are therefore research directions, not one universal summarizer.

## Skills/playbooks/procedures

Guidance requires provenance, version, applicability and precedence. Guidance does not grant Authority. Repeated trajectories can suggest procedures; validated procedures may migrate into Workflow machinery.

## Negative memory

The system should preserve contraindications/known bad applicability where useful, not only “successful tricks”. Learning invalidation is needed when upstream policies/runtime/artifacts change.

## Experiments

Bake off full transcript vs durable refs vs structured eviction vs summaries by runtime/agent; golden dependency tests; poisoning/stale-context tests; procedure mining in shadow; measure quality, tokens, latency and reconstruction failures.
