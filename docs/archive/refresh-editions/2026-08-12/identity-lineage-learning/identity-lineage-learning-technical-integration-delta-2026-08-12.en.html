Technical Integration Delta — Canonical Lineage & Adaptive Experience

Incremental technical proposal for absorbing the new research pack without creating an Identity Plane or new source of truth.

PROPOSED TARGET DELTAIMPLEMENTATION RESEARCHRECONCILE BEFORE CODE

1. Status and non-goals

PROPOSED / IMPLEMENTATION RESEARCH. Este delta integra semanticamente o pacote novo ao corpus. Não cria primitive, ADR, SPEC ou task canônica.

Non-goals: criar Identity Plane, adotar graph DB, reescrever Workflow/Authority/Evidence, habilitar learning, ou tocar no checkout dirty.

4. Golden qualification queries

  1. Which governed Work caused Effect E?
  2. Which Project/Subject revision was acted upon?
  3. Which RouteDecision/ExecutionBinding realized it?
  4. Under which Authority/policy epoch?
  5. Which attempt(s) correspond to one logical effect?
  6. Which evidence/evaluator changed Attribution/Reputation?
  7. Which experiences generated an Evolution Candidate?
  8. Who evaluated/promoted/rejected it?
  9. Can evidence from Project A legitimately update Project B?

5. Candidate BDDs for reconciliation

  1. Same Work survives runtime/model retry without identity collapse.
  2. Two attempts for one logical effect do not count as two effects.
  3. Observed OTel span cannot mint canonical effect/evidence.
  4. Policy epoch at execution is queryable after policy changes.
  5. Project-local evidence cannot update global prior without transportability qualification.
  6. Candidate cannot become promoter of its own evolution.
  7. Scrub/compaction preserves minimum lineage joins required by golden queries.
  8. External PROV/OpenLineage export is rebuildable and loss is declared.

6. Strangler slices

  1. S0 inventory IDs/refs/epochs read-only.
  2. S1 derived lineage view with zero behavioral changes.
  3. S2 golden-query coverage and ambiguity metrics.
  4. S3 close only proven missing joins via adapters/contracts.
  5. S4 archival survivability.
  6. S5 external projections (OTel/PROV/OpenLineage).
  7. S6 scoped Experience/Attribution offline/shadow.
  8. S7 evolution lineage/attestation.

7. Evidence and gates

Gates mínimos: reconstruction determinism, query answerability, ambiguity rate, no duplicate canonical identities, round-trip projection loss report, Windows/POSIX parity, no authority amplification, rebuildability, rollback by removing projection/adapters.

8. Research relationship additions

O ResearchObject novo deve ganhar edges para as linhagens existentes: RECENTERS Agent OS/Workflow; REFINES Governance/Audit, Interoperability e Research Methodology; CONSTRAINS Routing/Learning/Evolution pelo scope de evidence/applicability. O technical delta é DERIVED_FROM o pacote novo e permanece PROPOSED.

9. Pointers and promotion criteria

Pointers não viram gaps. Um pointer só chega a ADR candidate quando a reconciliation com CURRENT demonstrar missing semantic join, owner bounded context, BDD, migration seam, rollback e evidence gate. Caso contrário permanece RESEARCH_OPEN ou ALREADY_SATISFIED.

10. Exit criterion

Make the history queryable before making it learnable; make it verifiable before making it promotable.

Saída desta proposta: nenhum write no tare-tools; apenas um pacote de reconciliation futuro, independente, capaz de testar as golden queries contra repo/Git atuais.
