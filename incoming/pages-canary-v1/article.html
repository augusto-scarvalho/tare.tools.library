Canário de publicação SIGNAL para GitHub Pages

Documento canário de baixa autoridade destinado a exercitar o fluxo editorial, a projeção SIGNAL e as provas de preservação do GitHub Pages sem conceder autoridade de cutover.

RESEARCH. Este documento é evidência operacional de um caminho de publicação. Ele não cria TARGET, CURRENT, aprovação editorial nem autoridade para alterar o GitHub Pages público.

Escopo

O canário existe para provar um caminho mínimo, real e auditável entre um artefato HTML canônico e sua futura projeção de leitura. O efeito de produção permanece fora do escopo.

  • preservar o HTML canônico como source artifact;
  • exercitar idioma pt-BR, estrutura semântica e asset local;
  • fornecer alvos verificáveis para links e fragmentos;
  • produzir evidência que possa ser recalculada independentemente.

Ir para os achados do canário.

Método e evidência

O documento foi deliberadamente construído com uma superfície HTML pequena, mas heterogênea. O objetivo é detectar perdas que um fingerprint baseado apenas em texto corrido poderia não distinguir.

Gates que devem permanecer separáveis

Green CI é evidência de qualificação; não é autoridade para produzir um efeito de publicação.
Receipts esperados após publicação legítima
  1. PUBLICATION_RECORD ligado ao manifest e à decisão editorial;
  2. PROJECTION_RECORD com hashes e rewrite ledgers;
  3. PARITY_REPORT preservando o incumbent;
  4. CUTOVER_READINESS registrando blockers sem autoautorizar o cutover.

Achados esperados

Um canário aprovado deverá aparecer em um endereço aditivo sob /tare.tools.research/p/research-pages-canary-v1/, com o idioma preservado, o asset local resolvido e o link para #findings válido.

A seguinte invariável deve continuar verdadeira:

authority != green_ci
projection != canonical_source
merge_shadow != pages_cutover

Qualquer divergência entre essas relações é resultado de teste, não motivo para suavizar o gate.

Limitações

Este documento não prova sozinho equivalência visual completa, não testa referências cross-publication porque ainda não existe um segundo alvo canônico aprovado sob o mesmo contrato e não representa a diversidade do corpus histórico.

Browser/render evidence, aprovação editorial e autoridade de cutover continuam sendo gates externos e explícitos.
