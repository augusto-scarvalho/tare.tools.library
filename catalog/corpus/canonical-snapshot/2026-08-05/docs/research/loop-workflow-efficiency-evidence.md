## TOP LEADS FOR OUR PROBLEM

Ranked by how directly each attacks the two confirmed bottlenecks (re-gate churn, gate-as-constraint), tied to
the round's own briefs:

1. **Fingerprint-keyed gate-result cache (Nx / Turborepo / Bazel remote-cache pattern) → Brief A.**
   This is the highest-leverage lead because it's the *smallest delta from what we already have*: SPEC-157
   already computes a staged fingerprint. Nx/Turborepo/Bazel all implement exactly "hash inputs → on match,
   skip execution and replay the cached PASS" at production scale. We don't need to invent the mechanism,
   only wire our existing fingerprint into a cache-or-run decision before paying for a full 7-15 min re-gate
   on a tree that (partially) already passed. Confidence moderada→forte depending on which vendor's docs
   you weight; maturity producao across all three.

2. **Affected-target/test selection (Google TAP's reverse-dependency closure, bazel-diff, Ekstazi, pytest-testmon)
   → Brief A's other half.** Where the fingerprint cache answers "did this exact tree already pass," affected-
   target selection answers "which subset of the scenario+spec-pack surface does *this diff* actually touch."
   This is genuinely new work for us (we'd need a changed-paths → scenarios dependency map we don't have
   today), but every one of these four tools proves the pattern works at scale (Google: billions of test
   outcomes; Ekstazi: 32-54% time reduction measured across 32 OSS projects). Pair with lead #1: fingerprint
   cache kills *identical* re-runs, affected-selection kills *unnecessary* re-runs on genuinely new diffs.

3. **pytest-xdist-style sharding + independent-stage concurrency (GitLab/Jenkins job-parallelism) → Brief B.**
   Doesn't cut total compute — it trades machine/core count for wall-clock time — but it's cheap, doesn't
   touch correctness (same work, just concurrent), and is the most "just turn it on" of all five leads if the
   gate is CPU-bound and idle cores exist. Directly matches Brief B's "parallelize scenarios across cores;
   split spec-pack vs scenarios to run concurrently."

4. **Little's Law + Theory of Constraints/Drum-Buffer-Rope together → Brief B + C's theoretical spine.**
   These aren't techniques to install, they're the *proof* that the round's own diagnosis is structurally
   sound and the *sequencing rule* for exploiting it: DBR says never starve the drum (gate), pace releases
