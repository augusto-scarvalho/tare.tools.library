PROPOSED / Implementation Research · 2026-08-11

Cyclic Multi-Role Research Protocol — Technical Proposal

Executor-neutral contracts for staged research roles, immutable artifacts, adversarial cycles, explicit independence classes and evidence-bounded stopping.

PROPOSEDRESEARCH WORKFLOWSTRANGLER
Do not implement as new kernel primitives. Reconcile with canonical Workflow/Runtime/Capability/Evidence/Authority before any tare.tools implementation.

1. Status and non-goals

Status: PROPOSED / IMPLEMENTATION RESEARCH. This document specifies a research-workflow profile; it does not create Agent OS primitives. Non-goals: pretending sequential roles are independent agents, replacing peer review, creating a separate research runtime, or granting promotion authority to the workflow.

2. Ownership and canonical equivalents

Research Methodology owns the protocol definition in tare.tools.research. If automated by tare.tools, Workflow owns progression; Runtime executes a selected binding; Capability/Effects perform web/files/tool actions; Evidence records receipts/outcomes; Authority controls any promotion effect. `ResearchRole` is a local workflow role descriptor, not a kernel primitive.

3. Run contract

A run has `run_id`, research subject/pointer, architecture/corpus snapshot, executor identity, role plan, budget, stopping rule and assurance ceiling. Every role output is immutable/content-addressed after completion. Later roles reference prior artifacts and emit findings/deltas rather than rewriting them.

4. Functional roles

Default profile: Planner → Corpus Archaeologist → Consolidated Literature Scout → Bleeding-edge/Contradiction Scout → Source Curator → Evidence Analyst → Architecture Reconciler → Experimental Designer → Adversarial Reviewer → Revision Delta → Final Audit. Roles may be skipped only by an explicit profile with rationale. Social/personality personas are not part of the default.

5. Independence taxonomy

Record four dimensions separately: functional separation (different mission/checklist), context separation (shared vs fresh/artifact-only context), cognitive diversity (same vs different model/training family), and epistemic/authority independence (independent evaluator and promotion authority). Same-model sequential runs must say `epistemic_independence=NOT_INDEPENDENT`.

6. Evidence and revision semantics

A review finding identifies target claim/artifact, defect or uncertainty, evidence basis, severity and requested action. A revision is a new artifact linked to findings. Recency alone never overrides a prior claim. Negative evidence remains append-only. External/deterministic evidence can strengthen a correction but the model interpretation remains one interpretive family until independently validated.

7. Cycle and stop semantics

At least one adversarial cycle is required for the full profile. Repeat only when a material finding changes the synthesis or requires new evidence. Stop when no material evidence delta appears, blockers are resolved/OPEN, the budget is exhausted, or escalation is required. Never use “the model says it is satisfied” as the sole stop condition.

8. Assurance ceiling and escalation

Same-model final audit = screening. Strict or high-stakes claims require claim-appropriate independent evidence: deterministic validators, empirical experiments, heterogeneous model review and/or human/domain expert validation. The protocol must expose the ceiling rather than hide it behind reviewer labels.

9. Candidate machine-readable record

Proposed run fields: `run_id`, `profile_version`, `subject_refs`, `corpus_commit`, `architecture_epoch`, `executors[]`, `roles[]`, `artifact_refs[]`, `findings[]`, `revision_edges[]`, `evidence_family_refs[]`, `assurance_ceiling`, `stop_reason`, `external_effects`, `final_decision`. Keep JSON/JSONL + Git as canonical research-repo representation; projections remain rebuildable.

10. Migration strategy

S0 document-only/manual runs. S1 validator + hash manifest. S2 paired qualification on Frontier pointers. S3 optional tare workflow adapter in shadow. S4 heterogeneous executor support. S5 only after evidence: consider default use for risk/complexity classes. Rollback is trivial while the method remains a research-repo profile.

11. Candidate BDD

BDD-1 same-model roles never count as independent EvidenceFamilies. BDD-2 adversarial findings cannot silently overwrite prior artifacts. BDD-3 a role artifact records executor/model/runtime. BDD-4 a final same-model audit cannot emit strict-proof eligibility. BDD-5 cycles stop on evidence/budget/escalation criteria. BDD-6 a functional role can later bind to a different model/runtime without changing the research contract. BDD-7 promotion remains a separate authority path.

12. Qualification gate

Before default adoption, compare single-pass, compute-matched generic iteration, same-model CMRP, isolated same-model agents, heterogeneous agents and human/heterogeneous review over a stratified Frontier sample. Required metrics include contradiction recall, unsupported-claim precision, false-correction rate, negative-evidence preservation, architecture-duplication rate and cost-to-trust.

13. Authority note

CMRP is a Research Methodology profile. It can generate findings and implementation-research candidates. It cannot ratify TARGET, mint a Permit, approve its own promotion or claim independence that its executor topology does not provide.
