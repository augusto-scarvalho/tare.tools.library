1. Status and non-goals

PROPOSED / IMPLEMENTATION RESEARCH. Do not implement directly.

Non-goals: no Information/Repository Plane; no universal database migration; no ArtifactRef=OCI coupling; no event-source-everything; no OTel/OpenLineage proof authority; no implicit Task/Workflow redesign.

3. Golden queries before primitives

Can a Project revision be reconstructed from declared seed + inputs?
Which hidden/private/derived inputs are required?
Why does this Work exist and which demand revision caused it?
Is terminal execution also settled demand?
Which evidence became stale after artifact/source drift?
Which decisions/promotions consumed that evidence?
Can designated lineage/evidence queries survive compaction?
Can a foreign projection be removed without semantic loss?

4. Read-only views

First phase: Repository Boundary Inventory, Reconstructive Closure report, Context Reconstruction View, Evidence Recall query pack, and Settlement view. All rebuildable/read-only; none grants Authority.

5. Integration with Canonical Lineage v0.18

v0.18 asked whether canonical lineage can answer who/which Work/Authority/effect/evidence produced a result. v0.19 adds what must survive so those questions remain answerable after scrub, crash, rebuild, migration, compaction or upstream drift. Information Survival extends Canonical Lineage rather than replacing it.

6. Evidence Recall vs reuse

  • Recall: locate downstream dependents affected by change/revocation/freshness.
  • Reuse: decide whether historical evidence remains admissible for a current claim.

7. Reconstructive Closure qualification

Experiment on a Clean Project Seed rather than using a dirty checkout as sole evidence. Measure hidden inputs, time-to-reconstruct, semantic equivalence, Windows fidelity and independent reproducibility. Bit reproducibility remains a distinct level, not a universal requirement.

8. Demand / Task revision / settlement

Do not create Demand yet. First model queries for verbatim origin, clarification/disposition, revision delta, current scope, residual obligation, settlement owner and reopening trigger. Persistent ambiguity becomes a bounded-context gap candidate.

9. Technology adapters

OCI/ORAS, OpenLineage, OTel, SLSA/in-toto, Temporal/Restate/DBOS and MLflow remain mechanics/projection/lab candidates. Apply a semantic exit test and qualification pack.

11. Candidate BDDs / gates

  • session loss preserves durable Work/demand provenance;
  • deleting a derived projection is recoverable from declared inputs;
  • upstream drift invalidates dependent current evidence without rewriting historical verdict;
  • terminal execution with unmet demand is not settled;
  • candidate cannot control independent verifier interpretation;
  • Windows clean reconstruction preserves required semantics;
  • removing OTel/OpenLineage loses projection only;
  • private→distribution conflicts fail closed.

12. Rollback and authority

Initial slices are observe-only/shadow and removable without irreversible migration. Stable incumbent remains fallback. Research, derived views and external adapters have zero promotion authority.
