Research Knowledge Substrate — Technical Refinement Proposal

A repo-local, evidence-first model for identity, research objects, claims, provenance, enrichment and rebuildable projections in tare.tools.research.

PROPOSEDIMPLEMENTATION RESEARCHSHADOW FIRSTNO KERNEL PRIMITIVES
Status: PROPOSED IMPLEMENTATION RESEARCH. This document is not a ratified tare.tools architecture or Implementation Packet. It refines the accepted seven-part Research Lineage, Influence & Provenance section and proposes repo-local schemas/projections for tare.tools.research.

1. Design constraints

  • Historical and canonical bytes remain immutable.
  • Every derived object records provenance and source hashes.
  • Research metadata never grants Authority.
  • External APIs produce enrichment evidence, never silent truth.
  • JSON/JSONL remains the pragmatic storage baseline.
  • JSON-LD/RO-Crate/RDF are export/interchange projections first.
  • Embeddings and recommendations are disposable discovery projections.
  • Relations may be observed, curated or inferred; these states are never collapsed.

7. Source anchor

Use a Web-Annotation-like selector abstraction but keep implementation simple:

{
  "artifact_ref": "artifact:sha256:...",
  "selector": {
    "type": "html_fragment | heading | line_range | text_quote | git_blob_lines",
    "value": "..."
  },
  "content_digest": "sha256:..."
}

For regenerated editorial HTML, prefer heading/text selectors backed by source artifact hash; for code/current evidence, prefer Git blob/tree identity plus line/function context.

10. Enrichment provider boundary

Adapters should normalize only deterministic metadata fields where possible. Recommended initial providers:

  • Crossref — DOI/metadata/updates/funder/license identifiers.
  • DataCite — versions, translations, datasets/software and relation types.
  • Semantic Scholar — discovery, citation graph and embeddings/recommendations.
  • OpenAIRE — research-product graph and provenance/enrichment.
  • Software Heritage — precise archived software identities.

The normalized result is a candidate. Only deterministic exact identity relations can auto-promote; semantic support/challenge remains curated.

11. Validation strategy

Keep current JSON Schema tests. Add optional generated JSON-LD and SHACL validation as an interoperability qualification layer, not as the first source of truth. Proposed gates:

  • all artifact refs resolve and hashes match;
  • no dangling relation nodes;
  • inverse version/translation relations consistent;
  • no CURATED edge with only inferred basis;
  • no SAME_WORK without deterministic ID or explicit curation;
  • no claim marked OBSERVED without evidence refs;
  • no research relation can target a canonical authority object as if it grants promotion;
  • all compiled projections reproducible.

14. Candidate BDDs

Given two URLs with the same DOI
When identity resolution runs
Then they map to one ScholarlyWork but retain separate retrieval observations.

Given similar titles without a shared persistent identifier
Then SAME_WORK remains CANDIDATE until curated.

Given an embedding recommendation
Then it may create DISCOVERED_RELATED_TO
But must not create SUPPORTS.

Given a claim marked OBSERVED
Then at least one exact evidence/source anchor must resolve.

Given a source later marked RETRACTED
Then historical citation edges remain append-only
And dependent claims are marked REQUIRES_REVIEW, not deleted.

Given a generated JSON-LD/RO-Crate projection
Then deleting and regenerating it from canonical metadata yields equivalent semantics.

Given research metadata claiming a TARGET architecture change
Then it cannot mutate tare-tools canonical state without the normal promotion path.

16. Decision

Recommendation for refinement: adopt the seven-part human relationship section as the default future-document template, but introduce the Research Knowledge Substrate only through a shadow pilot. The strongest near-term slice is identity + ResearchObject + source anchors; claim-level modeling should follow only after we measure curation cost and usefulness.

17. Bibliography

  1. RO-Crate 1.3 — Research-object packaging with JSON-LD metadata, data entities and contextual entities.
  2. W3C PROV-O — Interchange model for provenance of entities, activities and agents.
  3. W3C SHACL — Validation of RDF graphs using explicit shapes and constraints.
  4. W3C SKOS — Lightweight knowledge-organization model for concepts, labels and broader/narrower relations.
  5. W3C Web Annotation — Body/target/motivation model for granular annotations and anchored commentary.
  6. DataCite versioning and related identifiers — Standard relation types for versions, translations, variants and related research objects.
  7. CiTO — Citation-intent vocabulary including supports, extends and uses-method relations.
  8. Open Research Knowledge Graph — Machine-actionable representation and comparison of scholarly contributions.
  9. ORKG FAIR literature surveys — Structured comparison of problems, methods, materials and results across literature.
  10. OpenAIRE Research Graph — Enriched scholarly graph with provenance, identifiers, deduplication and linked research products.
  11. Crossref REST API — Bibliographic metadata, funding, licenses, updates and persistent identifiers.
  12. Semantic Scholar API — Academic graph, citations, embeddings and recommendation/discovery services.
  13. Software Heritage SWHIDs — Persistent content-derived identifiers for archived source-code objects.
  14. Nanopublications — Atomic assertion + provenance + publication-info research objects.
  15. Micropublications — Semantic model for claims, evidence, support, challenge and annotations.
  16. PaperTrail — 2026 claim-evidence interface showing the value and cognitive cost of granular scholarly provenance.
  17. FAIR Digital Object Framework — Typed, persistently identified digital objects with metadata and predictable resolution.
  18. FAIREr / cognitive interoperability — Human explorability and semantic units as a complement to machine-actionability.
